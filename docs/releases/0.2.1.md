# Malapit 0.2.1 — Public address

Released November 26, 2026. Public beta: https://malapit.malapit-ph.workers.dev/.

## Change

The public website and installable web app now use `malapit`, without `test` in the address. App metadata, sharing previews, installation links and current documentation use that address.

The existing Cloudflare Worker was renamed in place, retaining its immutable ID, all nine encrypted secrets, its D1 database and Supabase project. No account, listing, inquiry, rental, bill, payment record or photo migration was needed. No schema or paid-plan change was made.

Supabase's Site URL points to the public origin. Its allowed return URLs include the exact new and old `/auth/callback` paths. Only these two URL settings changed; Google provider settings remain intact. Google's OAuth callback stays on Supabase.

The old address remains as a small compatibility Worker. Public pages, shared links and new sign-in attempts redirect to the new address with their path and query. Existing callbacks, API calls and assets from already-open tabs forward to the main Worker through a service binding, keeping their original URL, cookies and normal access checks. This Worker has no database, secrets or scheduled jobs; billing and notifications continue only on the main Worker.

## User impact

Users sign in again at the new address. Browser login cookies and notification permissions are private to each origin. Those who installed the previous app should install from the new address and enable notifications there. There were zero stored push subscriptions when the address changed. Account and rental records remain attached to the same Google user IDs.

This remains a public beta on the existing free services and within the existing application limits. Renters pay owners directly using the owner's receiving details; Malapit does not collect money or automatically verify transfers.

## Validation

- TypeScript, production build, and all 159 unit tests passed, including old-link routing and unchanged callback/API request forwarding.
- 34 deployed HTTP and Chrome checks passed: public pages and existing photos, matching published records, private access denial at both origins, cross-site write denial, callback handling, new Google OAuth initiation, old-origin browser sign-in navigation, metadata, mobile and desktop layout, service worker and installable manifest.
- Cloudflare bindings retain the original D1 ID and secret names. Only the main Worker has the five-minute billing/notification schedule.
- A new real Google account login, installation on a physical Android phone and lock-screen push delivery still require user/device verification. Automated checks stop at Google's sign-in screen and do not create real rentals, payments, or notifications.
