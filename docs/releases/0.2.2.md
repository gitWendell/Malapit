# Malapit 0.2.2 — Shorter free public address

Released November 26, 2026. Public beta: https://malapit.pages.dev/.

## Result

The public website and installable app now use the shorter Pages address. The existing `malapit` Worker still runs the app, authentication, private photos, D1 data, billing and notifications. Accounts and rental records stay attached to the same Supabase user IDs. No database, photo or credential migration was needed, and no paid plan was added.

Pages production forwards requests through its `MALAPIT` service binding. It retains each request's original origin, cookies, method, body, range headers and streamed response. Authorization, same-origin checks and private-photo checks remain in the existing app. Pages has no database or secret bindings. Preview deployments have no app service binding and return 404, including on API routes.

Both earlier Workers addresses redirect shared pages to the new address, keeping their paths and queries. Old sign-in links land on their intended screen on Pages before users start Google sign-in there. Directly redirecting an old-origin browser to `/auth/signin` would correctly fail its cross-site protection, so that protection remains unchanged. In-flight callbacks, API calls, sign-out and assets in old tabs keep their original URL and cookie host.

Supabase Site URL and its redirect allow-list were updated and read back after propagation. Both earlier exact callback URLs remain allowed. Google's OAuth callback remains on Supabase, and Google sign-in stays enabled. No signing keys or photo-storage keys were rotated.

## Deployment

Main app: the existing `npm run deploy` workflow.

Pages entry: `npm run deploy:pages`. The helper stages only the small Pages entry and config outside Vinext's generated configuration tree, deploys the `main` production branch, and removes its own temporary directory. It preserves the existing main-app build configuration. See `deploy/pages/wrangler.jsonc`.

Old `malapit-test` links: `wrangler deploy --config wrangler.legacy.jsonc`.

Only the main Worker has the existing five-minute billing/notification schedule. No schema migration was added. Existing free-service limits still apply.

## Verification

- TypeScript, production build and all **163 unit tests** passed. Added cases cover streamed request forwarding, preview-host denial, unchanged private operations, safe old sign-in destinations and redirect-loop prevention.
- **41 deployed HTTP and Chrome checks** passed, including both older addresses, private-access denial, cross-site write denial, existing published records/photos, metadata, Google OAuth initiation, old-tab sign-in navigation, mobile/desktop layout, service worker and installable manifest.
- A separate video range check returned HTTP 206 and exactly the requested 32 bytes through Pages.
- The main Worker retains all nine secret bindings and the same D1 ID. The compatibility Worker has no secrets, database or schedule. Pages production has only the existing app service binding; preview has none.
- No real rental, payment, notification or transfer was created during these checks. Completing a fresh real Google login at the new address, installing on a physical Android device and receiving a lock-screen notification still require user/device verification.

## Existing users

Sign in again at the Pages address. Browser cookies and notification permissions do not transfer across origins. Install the app from the new address and enable notifications there. There were zero stored push subscriptions before this switch. Existing accounts, listings and private rental/payment history remain in the original database.

Renters still pay owners directly using the owner's receiving details. Malapit does not collect money or automatically verify transfers.
